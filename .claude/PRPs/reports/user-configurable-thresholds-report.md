### D-2: `APPLY_DEBOUNCE_MS` を export した

- **WHY**: 「折りたたみを変えても再検出しない」テストが**デバウンスを越えて待つ必要があった**（下記 I-2）。テスト側に 250 を書き写すと 2 箇所に同じ数字が並ぶ。

## Issues Encountered

### I-1 ★ テスト #11 が「守っていないテスト」だった（変異テストで発覚）

計画に「`asPositiveInt` は 0 を弾く」という最重要の注意を書き、そのとおりに `asNonNegativeInt` を新設し、テストも書いた:

```ts
await chrome.storage.sync.set({ settings: { ...DEFAULT_SETTINGS, minBurstScore: 0 } });
expect((await getSettings()).minBurstScore).toBe(0);
```

**このテストは `asPositiveInt` に差し替えても通る。** 既定が 0 なので `asPositiveInt(0) ?? 0` が 0 を返し、**アサーションが真になる経路が 2 つある**。

変異テスト M8 で SURVIVED し、既定を一時的に 20 に差し替える形へ書き直して初めて捕捉できるようになった:

```ts
const original = DEFAULT_SETTINGS.minBurstScore;
DEFAULT_SETTINGS.minBurstScore = 20;
try { /* 保存された 0 と既定 20 を区別できる状態を作る */ } finally { ... }
```

**計画の段階で罠を正しく特定していても、テストの書き方が罠と同じ形をしていた。**

### I-2 ★ 「再検出しない」テストがデバウンスを見ていなかった（変異テストで発覚）

`<select>` の change に `scheduleApply()` を足す変異（M13）が SURVIVED した。原因は、テストが `selectFold()` の直後に同期で `expect(applyMock).not.toHaveBeenCalled()` を見ていたこと。**`scheduleApply` は 250ms 後に発火するので、同期のアサーションは必ず通る。**

`APPLY_DEBOUNCE_MS + 150` 待ってから見る形に直して捕捉できるようになった。

**「起きないこと」を検査するテストは、起きうる時刻を過ぎてから見なければ意味がない。**

### I-3 折りたたみの中で「ミュートしています…」が出ていなかった（変異テストで発覚）

`findCandidateItem` の探索範囲を `#candidates` から文書全体へ広げたが、**それを検査するテストが無かった**（M18 が SURVIVED）。応答を保留する `Promise` を使って途中の表示だけを観測するテストを追加した。

### I-4 フィクスチャが実機と違った（1 件・その場で修正）

`setupDom()` の `#fold-note` を空の `<p>` にしていたため、「解除の案内が背景タブで開く」テストが `missing element: #fold-note a` で落ちた。**Phase 8 で 3 周した「フィクスチャが実機と違うとテストは何も守らない」と同じ形**だが、今回はテストが即座に落ちたので実機に出る前に潰せた。

## 9b 撤回（2026-08-25・実装レビュー中）

ユーザーの指摘（逐語）:

> 投稿直後の集中の下限が意図と違う。悪意を持った投稿者がいたと仮定して、このアプリを見たら 120 分後にイイネすれば回避できるよね？

**回避できる。しかも上で「守られている」と報告したテストが、その回避を正しい挙動として固定していた。**

```ts
// 5 アカウントが 2 記事に共通、投稿の 90 分後に一斉いいね
const index = cluster({ author: 'example-author-a', items: [1, 2], accounts: 5, burstMinutes: 90 });
expect(detectCandidates(index, { ...DEFAULT_SETTINGS, minBurstScore: 50 }, NOW)).toEqual([]);
```

### なぜ撤回が正しいか

| | |
|---|---|
| **変数を握っているのが攻撃側** | 人数や記事数を減らすのは押し上げ効果そのものを削るので**コストがある**。時刻をずらすのは安い |
| **失敗が片方向で無音** | 下限を上げたユーザーは、取りこぼしたことに気づく手段がない。候補が減ったことは「効いた」ようにしか見えない |
| **公開が確定している** | 目的 2 は手法を記事にすること。「アルゴリズムが知られたら」は仮定ではない |
| **既に却下した指標と同型** | `emptyAccountRatio` を開放しない理由を、別の指標で作り直していた |
| **元のコードに歯止めがあった** | `burst.ts` に「補強スコアであって判定条件ではない」と書いてあり、実装時に自分で書き換えていた |

## 9f 窓内占有率（2026-08-25 追加実装）

ユーザーの要望「占有率をスライダーで動かせるようにしたい」から出発し、**`burstScore` を画面から降ろして占有率に置き換えた**。

```
窓内占有率 = 窓内にいいねしたクラスタのアカウント数 / 窓内にいいねした実人数
```

### なぜ置き換えたか（API 実測・匿名 33 リクエスト）

検出された候補を実データで裏取りしたところ、**拡張の表示は 4 つの数字すべてが実測と一致した**。そのうえで、`burstScore` では区別できないものが占有率では区別できた。

| | 60 分 | 180 分 | 2 日 |
|---|---|---|---|
| 著者 A（4 記事） | 76〜95% | 80〜88% | **80〜95%**（ほぼ平坦） |
| 著者 B（1 記事・総 72 いいね） | 75% | 79% | **43%**（一般票で薄まる） |

**720 分 → 1 日で記事全体が 38 → 61（+23）に跳ね、クラスタは +2 しか増えない。**一般の読者は 12〜24 時間後にまとめて来る。`burstScore` はこの差を出せない。

- **単調ではない。**最大は 60 分ではなく 120〜180 分（クラスタ自身がまだ全員押していないため）
- **99% には届かない。**60 分以内でも一般票が 5 件あり 75% が天井

### 実装

| 層 | 変更 |
|---|---|
| `domain.ts` | `LikeRecord.itemTotalLikes?`、`WindowShare`、`Candidate.windowShare` |
| `scanner.ts` | `foldLikes` が `Total-Count` をレコードに載せる（**捨てていた値**） |
| `burst.ts` | `windowShare()`。分母に**クラスタ外の liker も含む**。取りこぼしがあれば `null` |
| `rate-budget.ts` | `API_PER_PAGE` を新設（`qiita-client` は `vi.mock` されるので置けない） |
| `popup-state.ts` | `describeScores` → `describeWindowShare`。`describeEmptyAccounts` は作って**削除** |
| `popup-page.ts` | 見出しから「共通」を外し、空アカウント行を削除 |

### 実機フィードバックで 4 周した

| # | 指摘 | 原因 |
|---|---|---|
| 1 | 蓄積済みの候補が全部「測れません」 | **完全性判定を `Total-Count` の記録に依存させた。**それは新しく取った記事にしか付かず、`scanner` は既存記事を再取得しない → `per_page` 未満なら完全と確定できるようにした |
| 2 | 「顔ぶれ」は心象が悪い | 表示語彙を「**メンバー**」へ |
| 3 | `30 アカウントが 3 記事に共通` が **26 いいねの記事と矛盾** | **`clusterAccounts` は連結成分の和集合**で、全記事に共通する集合ではなかった。**結果の見出しを検査するテストが 1 件も存在しなかった** |
| 4 | `45 件` が 1 記事のいいね数を超える | (アカウント × 記事) の組で数えていた → **実人数**へ。見出しの「N アカウント」と単位が揃った |

### 変異テスト（3 ラウンド・すべて全捕捉）

| ラウンド | 結果 | 代表的な変異 |
|---|---|---|
| 実装直後 | **12 / 12** | 分母をクラスタだけにする / 取りこぼし検査を外す / 測れないときに 0% と言う |
| 完全性の緩和後 | **5 / 5** | 境界 `>=` を `>` にする / 上限の検査を外す |
| アカウント単位化後 | **7 / 7** | 組で数える / 分母をクラスタにする / 分子と分母を入れ替える |
