## Issues Encountered

### 1. 変異テストで「守っていないテスト」が見つかった（3 回連続）

「`findCard` の `null` を無視してリンク自体を隠す」変異を入れても、**全テストが通った**。

```ts
// 弱い版
document.body.innerHTML = `<div class="card"><a href="${url}">タイトル</a></div>`;
expect(countHidden()).toBe(0);
```

`<time>` が無いので `readTrendItems` が 0 件を返し、**`targets.size === 0` で早期 return していた。ループにすら入っていない。**

差が出る配置を作って直した:

```
正しいカード（<time> あり）        ← readTrendItems が著者を読む
カード外の同じ記事へのリンク       ← findCard が null
```

`null` を無視すると、**記事一覧と無関係な場所のリンクまで消える**。

**Phase 5b-1 → 5b-2 → 7 と 3 回連続で同じ形。**いずれも「アサーションが真になる経路が 2 つある」ものだった。

### 2. `chrome.runtime.sendMessage` の型で 2 回外した

`@types/chrome` の `sendMessage` は 5 つのオーバーロードを持ち、`vi.mocked` が **`void` を返すシグネチャ**を拾う。`mockResolvedValue` に値を渡せない。

- 1 度目: `setup.ts` のモック実装に戻り値型を付けた → **型は `@types/chrome` 由来なので効かない**
- 2 度目: `as unknown as SendMessage` → eslint が「不要なアサーション」と判定 → `--fix` が**アサーションごと削除**して元の型エラーに戻った

最終的に、モック設定の 1 行だけ `as never` で黙らせ、理由をコメントに書いた。**`setup.ts` の変更は戻した**（実 API に近づける変更だったが、型エラーの解決にならず、他のテストに影響を広げるだけだった）。

### 3. トップレベルで `chrome` に触ると未定義

```ts
const sendMessageMock = vi.mocked(chrome.runtime.sendMessage);  // ReferenceError
```

`setup.ts` は各テストの前にグローバルを用意するので、**モジュールのトップレベルではまだ `chrome` が無い**。関数に包んで解決した。

## 設計上の判断

### `hidden` 属性ではなくインラインの `display: none`

CLAUDE.md の教訓（Phase 6）:

> **CSS が hidden を殺した。** `display: flex` を足した瞬間、UA スタイルの `[hidden]{display:none}` が負けて要素が消えなくなった

Qiita 側の CSS がカードに `display` を指定していたら `hidden` は効かない。インラインスタイルは class より優先度が高い。**`!important` が使われていた場合だけ実機で判明する**ので、リスク表に対処法を書いた。

### `remove()` しない

戻せなくなる。OQ-16（誤検知でミュートすると視界から消えて再評価できない）と同じ形を、非表示でも作らない。

### 差分を追わず `unhideAll()` してから再適用

「誤り」に押し直したときに戻す必要がある。どの著者が増減したかを追うより、全部戻して付け直す方が単純で取りこぼしが無い。件数は 30 程度で、表示中の DOM を触るだけ。

### `SELECTORS` に新定数を入れなかった

`SELECTORS` は **Qiita 側の DOM を指すものの置き場**で、`selectors.test.ts` がハッシュクラス禁止を機械的に検査している。拡張自身が作る要素（`NOTICE_ID`）や自分で付ける目印（`HIDDEN_MARKER`）を混ぜると、**検査の意味が薄まる**。

### `unhideAll` は目印を見る

`[data-qtg-hidden="true"]` だけを戻す。`[style*="display"]` で全部戻すと、**Qiita 自身が隠している要素まで表示して UI が壊れる**。変異テストで固定した。

## 実機で見つかったバグ（2026-08-24）

### 動いたもの

- 30 枠のうち **2 件が消えた**（評価済み 2 件と一致）
- **「誤り」⇔「妥当」で消えたり戻ったりする**
- 右下の通知も出ていた（ユーザーが拡張機能のポップアップ内を探していただけ）

### 「表示する」を押したあと、隠し直せなかった

ユーザーの報告:

> 右下の表示を押した後、妥当を押しても消えない。誤りを押すと従来通りの動きになるがバグであると断定する。

**原因は `chrome.storage.onChanged` が「値が実際に変わったとき」だけ発火すること。**

```
「表示する」を押す   → unhideAll()。だが評価は valid のまま
「妥当」を押す       → 既に valid なので値が変わらない → onChanged が発火しない → 何も起きない
「誤り」を押す       → valid → false_positive に変わる → 発火 → 動く
```

**設計の誤りだった。** 「表示する」を押した後、画面は「表示中」なのにボタンは「表示する」のままで、**隠し直す先が無かった**。ユーザーが「妥当」を押したのは自然な発想だが、それは「評価する」操作であって「隠す」操作ではない。

### 修正 — 通知をトグルにした

```
2 件を非表示中  [表示する]
      ↓
2 件を表示中    [隠す]
      ↓
2 件を非表示中  [表示する]
```

- `renderNotice` に `mode: 'hidden' | 'shown'` を追加（既定は `hidden` なので既存の呼び出しは不変）
- content script に `shownByUser`（手で戻した件数）を持たせた
- **評価が変わったら `shownByUser` をリセット**して隠し直す

テスト 8 件を追加（`hider.test.ts` 5 / `content-script.test.ts` 3）。変異 3 項目すべてで落ちることを確認:

| 壊した箇所 | 落ちたテスト |
|---|---|
| トグルを元に戻す（「隠す」を消す） | 1 件 |
| モード変更時にボタン文言を書き換えない | 3 件 |
| 評価変更時に `shownByUser` をリセットしない | 1 件 |

### この発見が示したこと

- **`storage.onChanged` は「変更の通知」であって「操作の通知」ではない。** 同じ値を書き直しても発火しない。**ユーザーの操作を storage の変化で代用すると、冪等な操作が消える**
- **一方向のボタンは、押した後の状態を放置する。** 「表示する」を作ったとき、押した後にどうなるかを考えていなかった。**トグルでない操作は、戻る道が別に要る**
- 実機確認のチェックリストに「表示する を押す → 戻る」はあったが、**「その後どうするか」が無かった**。手順を 1 つずつ確かめても、**手順の間の状態は検査されない**

## 追加の要望（Phase 8 へ）

> 「ミュートも同時に行う。」があれば良さそうに考えた。`https://qiita.com/settings/mutes` でユーザー自身が確認できる。

**Phase 8 の Goal そのもの。** 隠すだけでは自分の画面にしか効かず、リロードのたびに拡張が隠し直している。OQ-9 が解決したので着手条件は揃っている。

設計判断が 1 つ残る（PRD の Phase 8 に記録すること）:

| 案 | |
|---|---|
| A | 「妥当」で**隠す＋ミュートも自動実行** — 手数は最小。誤って押すと `settings/mutes` から手で解除 |
| B | 「妥当」は隠すだけ。**別に「ミュートする」ボタン** |
| C | 候補一覧に「まとめてミュート」— PRD の Success signal（1 クリックで複数件）に一番近い |

**OQ-16 が効く** — ミュートするとその著者はトレンドから消え、以後スキャンの入力に現れない。適合率の再評価ができなくなるので、**評価を押してからミュートする順序は崩せない**。
