# Qiita Trend Cleaner

Qiita のトレンドを自分の基準で整理する Chrome 拡張機能です（Qiita 株式会社とは無関係の非公式ツールです）。短時間に同じメンバーからのいいねが集中している記事を検出し、評価に応じて一覧から隠せます。また、アクセストークンを設定すると記事の文体から「AI文体かも？」という目安も表示します。

> 旧称 Qiita Trend Guard。2026-08-29 にリポジトリ名へ合わせて改名しました。

## 仕組み

同じアカウントの集まりが複数の記事へ短時間にいいねしている共起パターンを、ブラウザに貯まったデータから見つけます。検出した著者はポップアップに並び、「妥当 / 誤り」をあなた自身が判断します。

判定の条件（人数・記事数・日数）はスライダーで変更できます。「妥当」と評価した著者はトレンド上から非表示になり、設定をオンにすれば Qiita 側のミュートも同時に行えます（初期設定はオフ）。一括での自動ミュートやブロック機能はありません。

### 不正とは決めつけません

この拡張機能が出すのは「いいねの重なり方」と「文体の目安」だけで、不正や規約違反を判定するものではありません。同じ組織やコミュニティの人たちが互いの記事を読んでいいねした場合も、同じパターンとして現れます。誤検知は起きるため、根拠の記事を確認したうえで判断してください。

## 現在の状態

Chrome ウェブストアには未公開です。開発者の環境で 8 件を評価したところ 8 件とも「妥当」でしたが、サンプル数が少なく評価者も開発者本人のため、実際の誤検知率はまだ分かりません（0/8 でも真の誤検知率が 3 割程度ある可能性は統計的に残ります）。

## インストール

```bash
npm install
npm run build
```

ビルドしたら Chrome で `chrome://extensions` を開いてデベロッパーモードを ON にし、「パッケージ化されていない拡張機能を読み込む」から `dist/` ディレクトリを選択します。その後 <https://qiita.com/trend> を開くとスキャンが始まります。

## 2 つの動作モード

| モード | 条件                         | 取得範囲                 | レート枠   |
| ------ | ---------------------------- | ------------------------ | ---------- |
| ライト | トークン未設定（初期設定）   | 表示中のトレンド記事のみ | 60 req/h   |
| フル   | Qiita アクセストークンを設定 | 著者の過去記事まで辿る   | 1000 req/h |

トークンの設定は任意です。[Qiita の設定画面](https://qiita.com/settings/applications)で `read_qiita` スコープのトークンを発行し、拡張機能の設定画面から保存してください。

### フルモードの機能: 「AI文体かも？」

トークンを設定すると、トレンド記事の右上に「AI文体かも？」と出ます。本文の文体（読点・太字・箇条書き・ダッシュ・「まとめ」見出し・特定の語彙など）をブラウザ内で数えた目安で、点数が高い記事だけ色付きで目立たせます（それ以外はカードにマウスを乗せたときだけ表示します）。地の文が 334 字未満の記事には「短文のため判定が甘い可能性あり」と添えます。

この目安は [Qiita の文章は生成 AI 以前と以後でどう変わったか](https://nyosegawa.com/posts/qiita-writing-before-after-ai/)の傾向をもとに計算しており、記事単体で AI 生成かを判定するものではありません。ラベルにマウスを乗せると左側に「そうかも / 違うかも」ボタンが出ます。あなたの感覚と目安の一致率を測るためだけに記録し、自動で条件を変えることはありません。

設定画面の「『AI文体かも？』の基準」では、次の項目を変更でき、開いているトレンドページにもすぐ反映されます。同じ画面で一致率（30 件たまると目標の 70% に届いたかを判定）も確認できます。

| 項目                               | 範囲 / 動作                                                | 初期設定 |
| ------------------------------------ | ---------------------------------------------------------- | ---------- |
| 何点以上で強調するか               | 1〜8 点（点数の計算や回答記録はそのまま）                  | 5 点     |
| 何字未満に「短文」の注釈を付けるか | 0〜2000 字（0 で注釈なし）                                 | 334 字   |
| 強調される記事を薄く表示する       | 対象カードを半透明にする（マウスを乗せると元の濃さに戻る） | オフ     |

## データの扱いと実装方針

データの保存や通信、コード上の制約は次のとおり定めています。

| 項目           | 内容                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 保存先と通信先 | 保存先はブラウザ内の `chrome.storage` のみ。通信先は Qiita 公式 API（`https://qiita.com/api/v2/`）のみ     |
| データの破棄   | 記事の本文は数えた直後に破棄して保存しない。いいねの記録と文体スコアは 7 日で自動削除                      |
| 要求する権限   | `storage` と `https://qiita.com/*` のみ（`tabs` や `alarms` は要求しない）                                 |
| スキャンと通信 | スクレイピングや定期実行はしない。トレンドを開いたときだけ走り、429 が返ったらその時点で止める             |
| DOM とログ     | セレクタは `src/dom/selectors.ts` に集約し `.style-*` は禁止。DOM 取得失敗時は `null` を返し例外を投げない |

## 開発

| コマンド            | 内容                    |
| ------------------- | ----------------------- |
| `npm run dev`       | HMR 付き開発サーバー    |
| `npm run build`     | 型チェック + 本番ビルド |
| `npm run typecheck` | 型チェックのみ          |
| `npm run test`      | ユニットテスト          |
| `npm run lint`      | ESLint                  |
| `npm run format`    | Prettier                |

設計の意図はソースコードのコメントに残してあります。`src/dom/selectors.ts` と `src/detect/` から読むと全体像を追いやすいはずです。
