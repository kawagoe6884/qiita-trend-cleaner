# Qiita Trend Cleaner

Qiita のトレンドから、**不自然ないいねパターン**が見られる記事を検出して隠す Chrome 拡張機能。

> 旧称 **Qiita Trend Guard**。2026-08-29 にリポジトリ名へ合わせて改名しました。

## これは何をするか

同じ顔ぶれのアカウントが、複数の記事に短時間で集中していいねしている——という**共起のパターン**を、
ローカルに蓄積したデータから検出します。検出した著者は一覧に出し、あなたが「妥当 / 誤り」を判断します。

- 判定は**あなたが決めた閾値**で行われます（開発者が追い込んだ固定値ではありません）
- 「妥当」と評価した著者は、任意で Qiita 側のミュートまで実行できます（**既定はオフ**）
- **一括自動ミュートはしません。** ブロックも行いません

### 断定はしません

この拡張は「**不自然ないいねパターン**」を示すだけで、不正や規約違反を断定しません。
同じ組織の人が互いの記事を読んでいいねするのは正常な行動であり、それも同じパターンとして現れます。

**誤検知は起こります。** 判断は必ずあなたが行ってください。

## 現在の状態

**ウェブストア未公開。** 未パック拡張として読み込んで使います。

開発者自身の環境で 8 件を評価し、8 件とも「妥当」でした。ただし**サンプルが小さく、
評価したのが開発者本人**なので、誤検知率は確定していません（0/8 でも、真の誤検知率が
3 割程度である可能性は統計的に排除できません）。この数字を信頼できる指標として扱わないでください。

## インストール

```bash
npm install
npm run build
```

1. Chrome で `chrome://extensions` を開く
2. 右上の **デベロッパーモード** を ON にする
3. **パッケージ化されていない拡張機能を読み込む** をクリック
4. このリポジトリの `dist/` ディレクトリを選択
5. <https://qiita.com/trend> を開くとスキャンが走ります

## 2 つのモード

| モード     | 条件                         | 取得範囲                 | レート枠   |
| ---------- | ---------------------------- | ------------------------ | ---------- |
| **ライト** | トークン未設定（既定）       | 表示中のトレンド記事のみ | 60 req/h   |
| **フル**   | Qiita アクセストークンを設定 | 著者の過去記事まで辿る   | 1000 req/h |

トークンは**必須ではありません。** 設定すると検出の材料が増えます。
[Qiita の設定画面](https://qiita.com/settings/applications)で発行し、拡張機能の設定画面から保存してください。

## データの扱い

- **保存先は `chrome.storage`（あなたのブラウザの中）だけ**です。外部サーバーへの送信は一切ありません
- 通信先は **Qiita の公式 API（`https://qiita.com/api/v2/`）のみ**
- アクセストークンは `chrome.storage.local` に保存され、Qiita 以外へ送られることはありません
- 収集するのは「どのアカウントがどの記事にいつ いいね したか」で、**一定期間で自動的に破棄**されます
- 権限は `storage` と `https://qiita.com/*` だけです（`tabs` も `alarms` も要求しません）

## 設計上の約束

- **スクレイピングをしない。** データ取得は**公式 API** と、**あなたが表示中のページの DOM 読み取り**のみ。
  HTML の自動 fetch は一切行いません（表示中の DOM を読むだけならリクエストは 1 本も増えません）
- **定期実行をしない。** スキャンはトレンドページを開いたときだけ走ります
- **レート枠を予測しない。** 429 が返るまで走り、返ったら止めます
- **DOM セレクタは `src/dom/selectors.ts` にのみ書く。** CSS-in-JS のハッシュクラス名（`.style-*`）は
  使用禁止（テストで機械的に強制）
- **DOM 取得の失敗は例外を投げず `null` を返す。** 誤った対象を操作するより何もしない方が無害
- **`console` を直接呼ばない。** `src/lib/logger.ts` を通します（ESLint で強制）
- **広告・収益化をしない**

## 開発

| コマンド            | 内容                    |
| ------------------- | ----------------------- |
| `npm run dev`       | HMR 付き開発サーバー    |
| `npm run build`     | 型チェック + 本番ビルド |
| `npm run typecheck` | 型チェックのみ          |
| `npm run test`      | ユニットテスト          |
| `npm run lint`      | ESLint                  |
| `npm run format`    | Prettier                |

設計の意図はソースコードのコメントに書いてあります。**なぜそう書いたか**を残す方針なので、
`src/dom/selectors.ts`（DOM への依存をここだけに閉じる理由）と `src/detect/`（判定の組み立て）から
読むのが早いはずです。
